# Penpot Design Engine — CodeLocal

## Decision

Penpot is a first-class CodeLocal Design Engine. CodeLocal does not clone Figma and does not ask users to install Penpot MCP manually.

### BA cases

1. **External MCP config** — user installs/configures Penpot MCP. Rejected because setup leaks into the user experience and does not satisfy the default-managed requirement.
2. **Auto-register external MCP** — CodeLocal writes a Penpot entry into the normal MCP registry. Better, but it still behaves like a removable third-party server and complicates credential/approval semantics.
3. **Managed hosted Design backend** — chosen. Penpot web services and the multi-user MCP server run as CodeLocal infrastructure. CodeLocal exposes the hosted endpoint as the reserved managed MCP server `penpot`; no Penpot server package is installed on user machines.

## Runtime architecture

```text
CodeLocal Dashboard
  └─ dashboard/design
       └─ iframe/HTTPS → design.codelocal.cloud (Penpot Frontend 2.17.0)
                    ├─ private → Penpot Backend :6060
                    │              ├─ shared CodeLocal Postgres → database `penpot`
                    │              ├─ shared CodeLocal Redis → logical DB 1
                    │              └─ Railway S3 bucket
                    ├─ private → Penpot Exporter :6061
                    └─ private → Penpot MCP :4401/:4402

CodeLocal local runtime
  └─ MCP Hub
       └─ reserved managed server: penpot
            └─ HTTPS → design.codelocal.cloud/mcp/stream?userToken=<encrypted runtime secret>
                         └─ frontend private proxy → Penpot MCP :4401
```

The Railway MCP service belongs to the hosted Penpot application and its built-in plugin flow. Each Penpot account generates its own MCP key under **Account → Integrations → MCP Server**. CodeLocal stores that key as an encrypted, workspace-scoped runtime secret and appends it as `userToken` only while opening the hosted MCP transport. The key is never written to the repository, registry, logs or model-visible server metadata.

## Railway production topology

Railway environment: `dev` (this is the existing environment currently serving
the production `codelocal.cloud` domains; this integration does not clone it or
create replacement services).

Public Design URL: `https://design.codelocal.cloud`

Services:

- `penpot-frontend` — `penpotapp/frontend:2.17.0`
- `penpot-backend` — `penpotapp/backend:2.17.0`
- `penpot-exporter` — `penpotapp/exporter:2.17.0`
- `penpot-mcp` — `penpotapp/mcp:2.17.0`
- `Postgres` — existing shared CodeLocal PostgreSQL service; Penpot owns logical database `penpot` inside the same instance
- `Redis` — existing shared CodeLocal Redis service; Penpot uses logical DB index `1` while CodeLocal keeps its own logical DB
- `penpot-assets-dev` — existing Railway S3-compatible bucket

**Hard rule:** Penpot must not provision `penpot-postgres`, `penpot-valkey`, or another Redis/Postgres service. Isolation is logical, not service-level.

All inter-service traffic uses Railway private networking. The public frontend is the only Penpot service exposed to browsers and MCP clients; its `/mcp/stream`, `/mcp/sse` and `/mcp/ws` routes proxy to the private MCP service.

The pinned 2.17.0 frontend image carries CodeLocal's backport of Penpot's dynamic nginx MCP upstream resolution fix. Each MCP route proxies through an nginx variable so Railway container IP changes are re-resolved instead of cached for the frontend container lifetime. Stream and SSE targets explicitly preserve `$is_args$args`; this is required so the per-user `userToken` reaches the multi-user MCP service.

### Production config

Penpot flags enable MCP and OIDC registration while disabling native password
login and native registration. CodeLocal remains the identity authority.

Assets use `PENPOT_OBJECTS_STORAGE_BACKEND=s3` with Railway bucket reference variables. Database, Redis and object-storage credentials are Railway references, not copied into source control. `PENPOT_SECRET_KEY` is generated by Railway's secret function and the exporter references the backend value.

Shared data layout:

```text
CodeLocal Postgres service
  ├─ existing CodeLocal database(s)
  └─ penpot                 # dedicated logical database, same Postgres instance

CodeLocal Redis service
  ├─ DB 0                   # CodeLocal/current default lane
  └─ DB 1                   # Penpot websocket/MCP coordination
```

Railway references for Penpot must resolve to the existing `Postgres.*` and `Redis.*` service variables. No Penpot-specific database/cache service is allowed in DEV or production.

## Managed MCP behavior inside CodeLocal

- `penpot` is a reserved MCP server name.
- It is always injected into the effective MCP catalog because it is a default-installed System Plugin.
- Normal users cannot shadow it with another registry entry.
- The production endpoint is `https://design.codelocal.cloud/mcp/stream` and exposes four remote-safe Penpot tools.
- A user connects the System Plugin once with the MCP key generated by their Penpot account. CodeLocal encrypts the key at rest and materializes it only into the selected runtime.
- The active Penpot file remains explicit execution context: the user opens the file and connects MCP from the Penpot workspace toolbar before design mutations run.
- `CODELOCAL_PENPOT_MCP_URL` and `CODELOCAL_PENPOT_MCP_CLI` remain development/debug escape hatches. A loopback URL may explicitly opt into the pinned local `npx` fallback, but the production package does not bundle or start Penpot MCP locally.
- Tool execution still passes through CodeLocal MCP call policy/approval boundaries; using the hosted backend does not bypass action safety.

## Dashboard behavior

The Dashboard Design route embeds the CodeLocal-owned Penpot origin. Penpot's
login screen starts the first-party OIDC flow through its existing
`POST /api/auth/oidc` handler; the iframe itself must stay on the public Penpot
origin rather than navigating to that API endpoint with `GET`. The thin
`Dockerfile.penpot-frontend` image keeps upstream Penpot unchanged while
replacing the default `X-Frame-Options: SAMEORIGIN` response with a narrow CSP
`frame-ancestors https://codelocal.cloud`. A new-tab link remains available as
a browser fallback.

The production frontend must use `railway.penpot-frontend.json`. Penpot 2.17.0
contains the upstream fix for the missing `/css/ui.css`; the image also creates
a compatibility symlink only when the upstream layer lacks that file. Verify
every deployment with:

```text
curl -I https://design.codelocal.cloud/css/ui.css
```

The response must be `200`, `Content-Type: text/css`, and must not contain
`X-Frame-Options: SAMEORIGIN`.

## CodeLocal OIDC provider

CodeLocal exposes these first-party endpoints from the existing Cloud service:

```text
/.well-known/openid-configuration
/.well-known/jwks.json
/oauth/authorize
/oauth/token
/oauth/userinfo
```

Authorization reuses the `codelocal_session` identity and the existing Redis
service for atomic, single-use authorization codes. ID/access tokens are EdDSA
JWTs; the stable signing key is derived from the existing `MCP_AUTH_SECRET`, and
only its public Ed25519 key is exposed through JWKS. No Penpot auth database is
created.

CodeLocal Cloud variables:

```text
CODELOCAL_PENPOT_OIDC_CLIENT_ID=codelocal-penpot
CODELOCAL_PENPOT_OIDC_CLIENT_SECRET=<shared Railway secret, 24+ characters>
CODELOCAL_PENPOT_OIDC_REDIRECT_URI=https://design.codelocal.cloud/api/auth/oidc/callback
```

Penpot frontend and backend variables:

```text
PENPOT_FLAGS=enable-mcp enable-access-tokens enable-login-with-oidc enable-oidc-registration disable-login-with-password disable-registration
PENPOT_PUBLIC_URI=https://design.codelocal.cloud
PENPOT_OIDC_NAME=CodeLocal
PENPOT_OIDC_CLIENT_ID=codelocal-penpot
PENPOT_OIDC_CLIENT_SECRET=<same shared Railway secret>
PENPOT_OIDC_BASE_URI=https://codelocal.cloud
PENPOT_OIDC_AUTH_URI=https://codelocal.cloud/oauth/authorize
PENPOT_OIDC_TOKEN_URI=https://codelocal.cloud/oauth/token
PENPOT_OIDC_USER_URI=https://codelocal.cloud/oauth/userinfo
PENPOT_OIDC_JWKS_URI=https://codelocal.cloud/.well-known/jwks.json
PENPOT_OIDC_SCOPES=openid profile email
PENPOT_OIDC_USER_INFO_SOURCE=userinfo
PENPOT_SSRF_ALLOWED_HOSTS=codelocal.cloud
```

Penpot uses its existing profile rows only as the workspace projection of the
CodeLocal `sub`/email identity. Password login and native registration are
disabled, so users do not create a second Penpot account.

## Production operations

Back up the shared Postgres `penpot` database and Railway S3 bucket, alert on
frontend/backend/exporter health, capacity-plan the shared Redis/Postgres
services, and keep the Penpot application and `@penpot/mcp` versions aligned
during upgrades.
